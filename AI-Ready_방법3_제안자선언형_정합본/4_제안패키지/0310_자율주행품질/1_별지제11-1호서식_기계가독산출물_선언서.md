# [별지 제11-1호서식] 기계가독 산출물 선언서 — TTAK.KO-11.0310
「정보통신표준화 운영요령」 제13조제5항에 따라 제출한다. 표준화과제 제안서(별지 제11호서식 — 개정 제안서)에 첨부한다.

**JSON 형태의 자율주행 학습용 데이터 품질 검증 지침 — 정확성 및 다양성** · TTAK.KO-11.0310 · PG604 (지능형 모빌리티) · 제안자 작성 · 파일럿 실증(AI-Ready 개정 제안)

> 이 선언서는 파일럿 실증을 위해 채운 **작성 예**다. 제안자가 제안 단계에서 선언하는 것은 네 가지다 — 어떤 외부 어휘를 규범적으로 쓸 것인가(2), 어떤 기계가독 산출물을 어떤 형태로 낼 것인가(3), 외부에 공개할 것인가(4), 어떤 이용조건으로 낼 것인가(5). 실제 산출물의 작성·제출은 초안 단계에서 에디터가 한다(운영요령 제19조의3제1항).

## 1. 제안 개요

| 항목 | 기재 |
|---|---|
| 표준화과제명 | JSON 형태의 자율주행 학습용 데이터 품질 검증 지침 — 정확성 및 다양성 (TTAK.KO-11.0310 AI-Ready 개정) |
| 제안자 | 에스에스엘㈜ (제안자가 에디터를 겸한다) |
| AI-Ready 적용 대상 여부 | ☑ 해당 ☐ 비해당 |
| 기술 대상 프로파일 | ☐ ① 지식정보 ☐ ② 자기기술형 레코드 ☐ ② 중 참조표준·물성 ☐ ③ AI 데이터세트 ☑ ④ 품질 지표 (별표 10 제2부) |
| 목표 수준 | ☐ 필수만 ☑ 권장까지 (별표 10 제2부의 기술 대상 프로파일별 요구 수준) |

**기술 대상 프로파일 판단 근거.** 데이터 자체가 아니라 데이터의 품질 — 품질 차원·지표·측정 방법 — 을 기술하는 표준이라 프로파일 ④에 든다. 특정 데이터세트를 기술하지는 않으므로 출처·운영이 성립하지 않는다. 그래서 필수는 L1에 머물고 품질(DQV)이 권장의 중심이 된다.

**목표 수준.** 필수 — 시맨틱 · 신태틱 (= L1). 권장 — + 품질 (DQV). 이 프로파일에서 특히 중요한 것 — 검증하는 품질 지표(정확성·다양성)를 형식 어휘(DQV)로 정의해, 지침이 규정한 품질을 기계가 계산·비교할 수 있게 하는 것.

> 목표 수준은 기술 대상 프로파일별 필수·권장으로 선언한다. 별표 10의 L1·L2·L3는 구성요소 묶음의 이름이며 목표 단계가 아니다. 여기 적은 기술 대상 프로파일과 목표 수준을 상정 단계의 자가점검표(별지 제21-1호서식) 0부에 그대로 옮긴다.

## 2. 어휘 선언 — 규범적으로 사용하는 외부 어휘

규범적으로 사용하는 어휘를 모두 적는다. 여기 적은 어휘는 표준초안의 **인용 표준에 등재**한다(작성지침 6.5.3). 사용 범위는 요소 정의표에 대응하는 클래스·속성 수이며, 요소에 대응하지 않고 부속서(출처 그래프·이용정책 등)에서만 쓰는 어휘는 그렇게 적었다.

| No. | 어휘명 | 네임스페이스 IRI | 사용 범위 | 이용조건 |
|---|---|---|---|---|
| 1 | Data Quality Vocabulary (DQV) | `http://www.w3.org/ns/dqv#` | 속성 4 / 부속서 A·B·C에서 사용 | W3C 소프트웨어·문서 라이선스 |
| 2 | Data Catalog Vocabulary (DCAT) 3 | `http://www.w3.org/ns/dcat#` | 클래스 1 · 속성 1 / 부속서 A·C에서 사용 | W3C 소프트웨어·문서 라이선스 |
| 3 | DCMI Metadata Terms | `http://purl.org/dc/terms/` | 속성 3 / 부속서 A·B·C에서 사용 | CC BY 4.0 |
| 4 | SKOS Simple Knowledge Organization System | `http://www.w3.org/2004/02/skos/core#` | 부속서 A에서 사용 | W3C 소프트웨어·문서 라이선스 |
| 5 | Shapes Constraint Language (SHACL) | `http://www.w3.org/ns/shacl#` | 속성 1 / 부속서 A·B에서 사용 | W3C 소프트웨어·문서 라이선스 |
| 6 | Web Annotation Data Model | `http://www.w3.org/ns/oa#` | 클래스 1 / 부속서 A·B에서 사용 | W3C 소프트웨어·문서 라이선스 |
| 7 | XML Schema Part 2: Datatypes | `http://www.w3.org/2001/XMLSchema#` | 데이터 유형(리터럴) | W3C 소프트웨어·문서 라이선스 |

> **이용조건 열은 제안자가 선언 시점에 확인한 값이다.** 모든 어휘를 **IRI로 가리키기만** 하고 정의문을 옮겨 적지 아니하므로 저작권 확인 대상이 아니며(작성지침 6.5.3 단서), 이용조건은 참고로 적는다.

> **ISO/IEC 5259-2(데이터 품질 차원)**는 부속서의 DQV 품질 차원을 정렬하는 기준으로 쓴다. 차원의 **이름과 번호를 가리키기만** 하고 정의문을 전재하지 아니하므로 작성지침 6.5.3 단서에 따라 인용 표준에 등재한다. 차원 식별자는 이 표준의 네임스페이스(`https://std.tta.or.kr/ns/iso5259-2#`)에서 자체 부여한다.

**자체 정의 요소**

기존 어휘에 대응 용어가 없는 요소는 이 표준의 네임스페이스(`https://std.tta.or.kr/ns/adq#` · `https://std.tta.or.kr/ns/iso5259-2#`)에서 자체 정의한다.

| No. | 요소 이름 | 자체 정의 사유 |
|---|---|---|
| 1 | annotations (어노테이션 참조) | 대응하는 기존 어휘 용어 없음 |
| 2 | attributes (속성) | 대응하는 기존 어휘 용어 없음 |
| 3 | label (라벨) | 대응하는 기존 어휘 용어 없음 |
| 4 | type (어노테이션 유형) | 대응하는 기존 어휘 용어 없음 |
| 5 | size (크기) | 대응하는 기존 어휘 용어 없음 |
| 6 | syntaxAccuracy (구문 정확성) | 대응하는 기존 어휘 용어 없음 |
| 7 | statSufficiency (통계 충분성) | 대응하는 기존 어휘 용어 없음 |
| 8 | statUniformity (통계 균일성) | 대응하는 기존 어휘 용어 없음 |
| 9 | accuracy (정확성 차원) | 대응하는 기존 어휘 용어 없음 |
| 10 | diversity (다양성 차원) | 대응하는 기존 어휘 용어 없음 |

> 기존 어휘에 대응 용어가 있으면 그것을 사용하고, 없을 때만 자체 정의한다. 자체 정의 요소도 요소 정의표의 모든 컬럼을 채우며, 전역 어휘 식별자(IRI) 컬럼에는 '자체 정의'로 적는다(작성지침 <표 6-5>).

## 3. 제공하는 기계가독 산출물

> 기계가독 산출물은 데이터의 구조·의미를 **정의**하는 것(표준의 규범 내용, 운영요령 제2조제1항제8호)이고, 참조구현은 그 정의를 **사용·처리**하는 것(표준의 일부가 아님, 제9호)이다. 아래는 모두 전자다. 검증 스크립트처럼 후자에 해당하는 것은 6에 적는다.

| 형식 | 제공 | 부속서 형태 | 비고 |
|---|---|---|---|
| JSON-LD @context | ☑ | ☑ 병행형 ☐ 참조형 | 부속서 A JSON-LD @context |
| JSON Schema | ☐ | ☐ 병행형 ☐ 참조형 | — |
| XML Schema(XSD) | ☐ | ☐ 병행형 ☐ 참조형 | — |
| RDF 어휘(Turtle 등) | ☑ | ☑ 병행형 ☐ 참조형 | 부속서 B SHACL 형상(값 제약 검증) · 부속서 C DQV 품질 측도 |

- **병행형**(원칙): 부속서에 전문 수록 + 별도 파일 제공 (작성지침 6.6 a). 부속서 수록본이 정본이다.
- **참조형**: 부속서에 규범적 참조 명세, 실물은 외부 저장소 (작성지침 6.6 b). 협회 보관본이 정본이다.

> 이 표준의 산출물은 모두 분량이 작고(각 수십 행) 표준 문서와 같은 주기로 개정되므로 전부 **병행형**으로 낸다. 참조형은 두지 아니한다.

> 부속서 번호는 작성지침 6.6의 **A, B, C 순 부여 원칙**에 따른다. 원 표준에 부속서가 있으면 그다음 알파벳부터 부여하며, 아래 번호는 개정부 초안 작성 편의상 A부터 적은 것이다.

## 5. 이용조건 (라이선스)

| 항목 | 기재 |
|---|---|
| 적용 라이선스 | ☑ CC BY 4.0 ☐ CC0 1.0 ☐ 기타 ( ) |
| 파일 내 표시 방법 | ☑ 주석 ☑ `$comment` 키 ☑ `dcterms:license` 트리플 |

**형식별 표시 방법**(작성지침 6.6)

| 산출물 형식 | 이 표준에서의 표시 방법 |
|---|---|
| Turtle(SHACL 형상·출처 그래프·단위·품질) | 파일 머리말 주석 + `<> dcterms:license <…>` 트리플(기계 판독용) |
| JSON-LD(@context·ODRL·Croissant) | 주석을 쓸 수 없으므로 최상위 `$comment` 키 + `http://purl.org/dc/terms/license` 키 |

> 이용조건은 **파일 자체에서 확인할 수 있어야** 한다(운영요령 제19조의3제7항). 별도 약관 페이지에만 두는 방식은 인정하지 않는다. 부속서에 수록한 경우에도 파일에 별도로 표시한다. 이 이용조건은 **산출물(스키마) 자체**의 것이며, 이 표준을 따라 쌓이는 데이터의 이용조건(별표 10 구성요소 ⑦)과는 별개다.
