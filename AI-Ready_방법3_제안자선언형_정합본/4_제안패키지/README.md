# 방법3 제안패키지 — 파일럿 실증 5종

**제안자가 선언하고 에디터가 산출물까지 작성하는 방법3의 절차를, 실제 표준 다섯 종에 끝까지 적용해 본 결과물이다.** 방법3의 서식(별지 제11-1호서식·제21-1호서식)과 작성지침 개정안(6.5.3·6.5.7·6.6·6.7)대로 문서를 쓰면 무엇이 나오는지, 그 결과가 별표 10 제4부의 산출물 요건을 실제로 통과하는지를 보인다.

작성일: 2026-10-27 · 정본은 md, hwpx는 md에서 생성한다(`도구/build_hwpx.py`).

## 방법2 패키지와 무엇이 다른가

방법2(공동 에디터 보강형)의 제안패키지(`../../AI-Ready_방법2_공동에디터보강형/AI-Ready_제안패키지/`)를 출발점으로 삼았으나 **문서는 전부 새로 썼다.** 방법2 패키지는 공동 에디터가 어휘 매핑과 부속서를 설계한다는 전제라서 방법3에 그대로 쓸 수 없다.

| 방법2 패키지 | 방법3 패키지 | 바뀐 이유 |
|---|---|---|
| 1 선언(목표 수준 신청) — 프로파일·목표만 | 1 별지 제11-1호서식 — 어휘·산출물 형식·형태·공개·이용조건·참조구현까지 | 방법3은 제안자의 **선언**이 품질 관문의 기준이다 |
| 2 표준초안 — IRI 열을 "공동 에디터"가 채움 | 2 표준초안 — IRI 열을 **에디터**가 채우고, 부속서에 "(본 부속서는 표준 내용의 일부임)"과 이용조건을 명기 | 작성지침 6.5.7·6.6 개정안 |
| 3 부속서설계명세(공동 에디터 작성) | **없음** — 설계 근거는 표준초안 각 부속서의 "설계" 항과 4.4~4.6으로 흡수 | 방법3에는 공동 에디터가 없다 |
| 4 자가점검표 — 등급·정합성·제출 목록 | 3 별지 제21-1호서식 — **3부 선언 일치·4부 산출물 요건 이행** 추가 | 별표 10 제4부 |
| 부속서 파일 — 파일 안에 이용조건 없음 | 부속서 파일 — **머리말 주석 + `dcterms:license` 트리플**(Turtle), **`$comment` + `dct:license` 키**(JSON-LD) | 운영요령 제19조의3제7항 |

부속서 파일의 **스키마 내용 자체는 방법2 것과 같다.** AI-Ready의 정의와 산출물은 추진 방법에 따라 달라지지 않기 때문이다. 달라진 것은 파일 머리의 이용조건 표시뿐이며, 그래서 무결성 값(sha256)은 방법2 파일과 다르다.

## 파일럿이 보여 주는 것

- **에디터 혼자 매핑해도 절차가 돌아간다.** 다섯 표준 모두 선언 → 초안 → 자가점검을 한 사람(에디터)이 끝냈고, 선언한 어휘와 요소 정의표의 IRI 컬럼이 일치한다(3부 1번).
- **산출물 요건은 내용 등급과 별개로 떨어질 수 있다.** 방법2의 부속서 파일은 내용 등급은 높았지만 파일 안에 이용조건이 없어 별표 10 제4부 6번(파일 자체에서 이용조건 확인)을 통과하지 못한다. 이 패키지는 그 한 가지를 고쳐 통과시켰다.
- **참조형은 명세 다섯 항목(위치·버전·무결성 값·이용조건·보관본)을 쓰면 끝난다.** 1594 부속서 E가 그 예다.

## 전제와 한계 — 읽을 때 유의

- **외부 공개 URL과 참조구현 위치는 예시다.** `https://github.com/<제안기관-저장소>/…`로 적었고 실제 공개 시 확정한다. 1594의 참조구현(pySHACL 검증 스크립트)도 선언 예시이며 이 저장소에 실물이 없다.
- **요소 정의표의 정의·기본값·예시 컬럼은 생략했다.** 개정부 중심 초안이라 원 표준의 요소 상세를 계승한다고 적었다. 통합본에서는 <표 6-5>에 따라 모두 채워야 한다.
- **부속서 번호는 A부터 적었다.** 원 표준에 이미 부속서가 있으면 그다음 알파벳이 된다(작성지침 6.6). 원 표준의 부속서 유무는 확인하지 않았다.
- **자가점검표의 등급은 개정 초안 기준이다.** 산출물이 있으면 2, 없으면 원 표준의 등급을 유지했다. 등급 판정 자체는 에디터의 자기 평가이며 제3자 검증을 거치지 않았다. 이것이 방법3이 감수하는 위험이다(설계 개요 5절).
- **어휘의 이용조건 열은 참고값이다.** 모든 어휘를 IRI로 가리키기만 하므로 저작권 확인 대상이 아니다(6.5.3 단서).
- 성명·일자·서명란은 비워 두었다.

## 다시 만들기

```
python 도구/build_hwpx.py          # 각 표준 폴더의 md 3종 → hwpx
python 도구/build_downloads.py     # hwpx 사본·부속서 ZIP → docs/downloads/제안패키지/, downloads.html 표 갱신
```

웹(GitHub Pages)에서는 https://suntae-kim2020.github.io/tta-work/downloads.html#pkg 에서 같은 파일을 내려받을 수 있다. hwpx나 부속서를 고치면 `build_downloads.py`를 다시 돌려 웹 사본을 맞춘다.

md가 정본이다. 부속서 파일(`부속서/`)은 표준초안 2의 수록본과 같은 내용이어야 하며, 파일을 고치면 표준초안의 수록본과 sha256도 함께 고친다.
