2. 어휘 선언 — 규범적으로 사용하는 외부 어휘

규범적으로 사용하는 어휘를 모두 적는다. 여기 적은 어휘는 표준초안의 인용 표준에 등재한다(작성지침 6.5.3).

No. 요소 이름 자체 정의 사유
1 대응하는 기존 어휘 용어 없음

기존 어휘에 대응 용어가 있으면 그것을 사용하고, 없을 때만 자체 정의한다.

가리키기와 옮겨 적기를 구분한다. 외부 어휘를 IRI로 가리키기만 하는 경우에는 저작권 확인 대상이 아니며, ISO/IEC·KS 표준도 작성지침 6.5.3 단서에 따라 인용 표준에 등재한다. 정의문·요소 설명을 옮겨 적는 경우에만 해당 기구의 저작권 정책을 확인하며, ISO/IEC·KS 표준은 옮겨 적을 수 없다.

3. 제공하는 기계가독 산출물

무엇이 기계가독 산출물이고 무엇이 참조구현인가

성격 표준에서의 지위
기계가독 산출물 데이터의 구조·의미를 정의한다 표준의 규범 내용 (제2조제1항제8호)
참조구현(6) 그 정의를 사용·처리한다 표준의 일부가 아님 (제9호)

변환기·검증기처럼 양쪽에 걸친 산출물은 어느 쪽으로 낼지 여기서 밝힌다. 규범으로 낼 것이면 3에, 참고로 낼 것이면 6에 적는다.

형식 제공 부속서 형태 비고
JSON-LD @context □ □ 병행형 □ 참조형 요소↔IRI 매핑
JSON Schema □ □ 병행형 □ 참조형
XML Schema(XSD) □ □ 병행형 □ 참조형
RDF 어휘(Turtle 등) □ □ 병행형 □ 참조형
기타 ( ) □ □ 병행형 □ 참조형

형태는 산출물마다 따로 고른다. @context처럼 분량이 작으면 병행형, 검증용 스키마처럼 분량이 많거나 개정 주기가 다르면 참조형이 된다. 한 표준에서 둘이 섞이는 것이 일반적이다.

부속서에 수록만 하고 파일을 제공하지 않는 방식은 인정하지 아니한다.

  • 병행형(원칙): 부속서에 전문 수록 + 별도 파일 제공 (작성지침 6.6 a)
  • 참조형: 부속서에 규범적 참조 명세, 실물은 외부 저장소 (작성지침 6.6 b)

부속서 번호는 작성지침 6.6의 A, B, C 순 부여 원칙에 따른다. 기계가독 산출물이라 하여 특정 알파벳을 고정하지 아니한다.

4. 외부 공개 (선택)

기계가독 산출물을 외부 저장소에 공개하는 경우에만 작성한다.

저장소 URL

협회는 표준 채택 시점의 사본을 보관하며, 보관본과 외부 공개본이 다를 경우 보관본에 따른다(운영요령 제19조의3제6항).

형식별 표시 방법(작성지침 6.6)

형식 방법
XSD·Turtle·Protobuf 주석으로 파일 머리말에 기재
JSON Schema 최상위 $comment 키에 기재 (JSON은 주석 불가)
RDF 어휘 dcterms:license 트리플로 기재

이용조건은 파일 자체에서 확인할 수 있어야 한다(운영요령 제19조의3제7항). 별도 약관 페이지에만 두는 방식은 인정하지 않는다. 부속서에 수록한 경우에도 파일에 별도로 표시한다.

참조구현은 표준의 일부가 아니며, 협회는 그 내용에 대하여 보증하지 아니한다(운영요령 제19조의3제8항). 위치는 표준초안의 자유 작성 부록에 기재한다(작성지침 6.7).

7. 제안자 확인

위 선언 내용은 표준초안의 요소 정의표 및 부속서와 일치하도록 작성하며, 상정 시 자가점검표(별지 제21-1호서식)로 일치 여부를 확인받는 데 동의합니다.

선언한 산출물의 실제 작성·제출은 초안 단계에서 에디터가 수행한다(운영요령 제19조의3제1항). 제안자가 에디터로 지정되면 같은 사람이다.
