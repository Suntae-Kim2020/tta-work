참조형 산출물의 부속서 양식(작성지침 6.6 b)). 작성지침 6.6 b)(참조형)에 따라 표준초안의 부속서로 작성한다.

산출물 분량이 많거나, 표준 문서와 다른 주기로 개정되거나, 다른 파일을 인용·포함하여 단일 파일로 완결되지 아니하는 경우에만 사용하며, **병행형(6.6 a)이 원칙**이다. · > **부속서 번호는 고정하지 아니한다.** 아래 예시는 부속서 X로 적었다. 실제 번호는 작성지침 6.6의 **A, B, C 순 부여 원칙**에 따르며, 기계가독 산출물이라 하여 특정 알파벳을 지정하지 않는다. 이미 부속서를 가진 표준이라면 그다음 알파벳이 된다.

부속서 X 기계가독 산출물

(본 부속서는 표준 내용의 일부임)

X.1 규범성

이 부속서가 지정하는 기계가독 산출물은 본 표준의 규범 내용이다. 산출물에 적합하지 아니한 구현은 본 표준에 적합하다고 할 수 없다.

X.2 산출물 명세

참조형 산출물이 여럿이면 X.2~X.5를 산출물마다 반복하거나, 아래 표에 행을 늘려 적는다.

항목 기재
산출물 이름
형식 JSON Schema / XML Schema / Turtle / JSON-LD @context 등
판·버전
무결성 확인 값 sha256:
이용조건

다섯 항목은 「정보통신표준화 운영요령」 제19조의3제4항 각 호(공개 위치·판 또는 버전·무결성 확인 값·이용조건·협회 보관본의 위치)에 대응한다. 공개 위치와 보관본 위치는 X.3에 적는다.

X.3 소재

구분 위치

보관본과 외부 공개본의 내용이 다른 경우에는 보관본에 따른다(「정보통신표준화 운영요령」 제19조의3제6항).

X.4 구성 파일

산출물이 여러 파일로 이루어진 경우 모두 적는다. 다른 파일을 include·import하는 진입점 파일을 명시한다.

No. 파일명 역할 무결성 확인 값
1 진입점
2 모듈

진입점 표시는 실무상 필수다. 국제 사례 조사에서 OGC gml.xsd와 ISO mdb.xsd가 다른 모듈을 include하는 진입점일 뿐이어서, 그 파일만 내려받으면 동작하지 않는 문제가 실제로 확인됐다.

X.5 일괄 내려받기

구성 파일이 여럿인 경우 개별 파일 주소와 함께 일괄 내려받기 경로를 제공한다.

항목 위치
압축본

X.6 인용 어휘

이 산출물이 규범적으로 사용하는 외부 어휘. 본문의 인용 표준과 일치하여야 한다.

어휘명 네임스페이스 IRI 이용조건 사용 방식
☐ IRI로 가리킴 ☐ 정의문 전재

사용 방식을 밝힌다. IRI로 가리키기만 하는 경우에는 저작권 확인 대상이 아니며, ISO/IEC·KS 표준도 작성지침 6.5.3 단서에 따라 인용 표준에 등재한다. 정의문을 전재하는 경우에만 해당 기구의 저작권 정책을 확인하며, ISO/IEC·KS 표준은 전재할 수 없다.

작성 시 유의사항

하나. 버전과 무결성 확인 값을 반드시 적는다. 외부 저장소는 변경될 수 있으므로, 이 두 값이 "표준이 지정한 그 산출물"을 특정한다.

둘. 파일명에 버전을 넣는 규칙을 권장한다(예: mods-3-8.xsd). 파일명이 바뀌면 문서의 링크가 깨진다. 국제 사례에서 HL7 FHIR의 definitions.shex.zip이 fhir.schema.shex.zip으로 바뀌어 기존 문서의 링크가 무효가 된 사례가 확인됐다.

셋. 이용조건은 이 명세뿐 아니라 산출물 파일 자체에도 표시한다(작성지침 6.6).

넷. 항목 번호는 작성지침 5.3.3·6.8.1 e)의 체계(a) → 1) → (a) → (1) → (가))를 따른다. 원문자(①②③)는 쓰지 아니한다.
