# AI-Ready 표준화 방법1 — 제안자 선언형

**표준 제안자가 어휘를 선언하고, 그 선언에 따라 에디터가 기계가독 산출물(스키마)까지 작성한다. 협회는 별도의 어휘 전문가를 배정하지 않는다.**

> 이 폴더는 **그 자체로 완결된 제안 패키지**다. 규범 개정안·서식·근거·보고서 자료가 모두 안에 있다.
> [방법2(공동 에디터 보강형)](../AI-Ready_방법2_공동에디터보강형/)과는 **별개의 독립 개정안**이며, 현행 규범을 기준으로 작성했고 방법2를 참조하거나 전제하지 않는다. TTA 보고서에서는 두 방법을 함께 제안한다.

## 핵심 설계

**1. 스키마는 규범이다.** 참고 자료가 아니다. 따라서 부속서 수록(또는 규범적 참조), 지식재산권 확인, 협회 보관, 라이선스 명시가 모두 따라 나온다.

**2. 외부 공개를 허용하되 보관본이 정본이다.** GitHub 등에 공개할 수 있으나, 협회가 채택 시점 사본을 보관하고 외부 공개본과 다르면 보관본에 따른다. CycloneDX가 GitHub 배포와 Ecma 정식 승인을 병행하는 구조와 같다.

**3. 참조구현 코드는 표준이 아니다.** 위치를 부록에 안내할 수 있을 뿐이며 협회는 보증하지 않는다.

## 근거 — 국제 선례

방법1의 각 조문은 [3_근거_국제선례/](3_근거_국제선례/)의 조사에 기반한다.

| 갈래 | 대상 | 핵심 발견 |
|---|---|---|
| 산출물 배포 방식 | 16개 표준 | **문서 안에 스키마를 담은 사례 0건.** ECMA-424조차 GitHub를 규범적으로 참조 |
| 거버넌스·절차 | 표준화 기구 6곳(IETF·W3C·Ecma·OASIS·OGC·ITU-T) | Ecma TC39 챔피언 모델 · IETF TLP 제4조 코드 컴포넌트 |

**선례의 무게는 기구 성격에 따라 다르다.** 공식 표준화 기구 → 국가기관 → 국제표준화된 단체 → 기업 컨소시엄 순이며, [3_근거_국제선례/README.md](3_근거_국제선례/README.md)에 사례별로 표시해 두었다. Schema.org·Croissant는 표준화 기구가 아니므로 인용 시 그 점을 밝히는 편이 안전하다.

### 별표 10·별지 제21-1호는 방법1용으로 별도 작성했다

기존 작업물(`../AI-Ready_방법2_공동에디터보강형/AI-Ready_수준요건_명세서_v0.3.docx`, `AI-Ready_자가점검표.docx`)은 본문이 **공동 에디터를 전제**하고 있어 그대로 쓸 수 없다(각 10회·4회 언급 확인). 그래서 방법1용을 따로 만들었다.

**승계한 것** — 7개 구성요소 등급 기준, L1·L2·L3 묶음, 프로파일별 요구 수준, 성숙도 산식, 정합성 자가검증 7개 항목. AI-Ready의 정의는 추진 방법에 따라 달라지지 않으므로 `수준 요건 명세서 v0.3`의 체계를 그대로 따랐다.
