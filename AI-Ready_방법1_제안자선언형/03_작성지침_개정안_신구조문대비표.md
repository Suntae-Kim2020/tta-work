# 정보통신단체표준 작성지침(TTAR-09.0040) AI-Ready 개정(안) — 방법1

신구조문대비표 · 안건 ② · 전략계획위원회·TC 심의(운영규정 제47조제1항)
기준: TTAR-09.0040/R1(2025.5.23.)

> 안건 ①(운영요령)이 먼저 의결되어야 한다. 이 지침이 운영요령 제19조의3을 참조하기 때문이다.

---

## 1. 개정 이유

「정보통신표준화 운영규정」 제38조제3항은 표준초안 작성 방법을 이 지침에 위임한다. 방법1에서 **표준 제안자가 직접 어휘를 선언하고 기계가독 산출물을 작성**하므로, 그 작성 방법을 지침에 규정한다.

**분석 근거.** 데이터를 기술하는 표준 20종을 실측한 결과, 외부 어휘·스키마에 규범적으로 의존하면서 이를 인용 표준에 등재하지 않은 사례가 20종 중 18종(90%)에서 발견됐다. 개별 표준이 아니라 작성 방법의 문제이므로 지침을 정비하여 해소한다.

**추가 근거.** 국제 표준화기구 16개 사례를 실물 수집·검증한 결과, **표준 문서 파일 안에 스키마 전문을 담은 사례는 0건**이었다. ECMA-424(CycloneDX)조차 566쪽 본문에 스키마 코드가 없고 외부 저장소를 규범적으로 참조한다. 이 관행을 6.6에 반영한다.

## 3. 신구조문대비표

### 3.1 6.5.3 인용 표준 (보강)

| 현 행 | 개정(안) |
|---|---|
| 인용 표준이란 표준 작성 시 전부 또는 부분적으로 직접 인용한 표준으로, 작성하는 표준의 적용을 위해 필수적인 표준을 말한다.<br><br>모든 표준을 다 인용할 수 있는 것은 아니므로, 해당 표준화기구나 단체의 저작권 정책을 확인하여야 한다. TTA와 준용 협약을 맺은 기관 중 IEEE와 ETSI는 부속서 A에 정리되어 있으므로 참조한다. | (현행 유지)<br><br>**표준이 본문 또는 부속서에서 외부 어휘 또는 스키마(예: W3C DCAT·SKOS·DCMI Terms, W3C XML Schema 데이터 타입, ISO/IEC 표준 등)의 클래스, 속성, 데이터 타입 중 어느 하나 이상을 규범적으로 사용하는 경우에는, 해당 어휘 또는 표준을 인용 표준에 등재한다. 규범적으로 의존하면서 '인용 표준 해당없음'으로 기재하지 아니한다.**<br><br>**인용 표준과 참고 문헌은 규범적 의존 여부로 구분한다. 따르지 않으면 이 표준에 적합하다고 할 수 없는 문서는 인용 표준에, 이해를 돕는 정보 제공에 그치는 문서는 참고 문헌에 둔다.**<br><br>**외부 어휘를 전역 어휘 식별자(IRI)로 가리키는 것과 그 정의문을 이 표준에 옮겨 적는 것은 구분한다. 식별자로 가리키기만 하는 경우에는 저작권 확인 대상이 아니며, 정의문·요소 설명 등을 옮겨 적는 경우에만 해당 기구의 저작권 정책을 확인한다.** |

> **마지막 문단이 실무상 가장 중요하다.** 인용(가리킴)과 전재(옮겨 적음)를 혼동해 불필요한 저작권 확인에 시간을 쓰거나, 반대로 전재하면서 확인을 누락하는 일을 막는다.

### 3.2 6.5.7 요소 정의표 (신설)

| 현 행 | 개정(안) |
|---|---|
| 〈신설〉 | **6.5.7 요소 정의표**<br><br>**데이터의 요소(항목)를 정의하는 표준은 각 요소를 아래 정규 컬럼을 갖춘 표(이하 "요소 정의표")로 작성한다. 요소 정의표는 사람이 읽을 수 있도록 작성하며, 기계가독 형식으로의 변환은 6.6에 따른다.**<br><br>**① 요소 이름 ② 표시명 ③ 정의 ④ 데이터 유형 ⑤ 값 영역 ⑥ 다중성 ⑦ 필수 여부 ⑧ 기본값 ⑨ 예시 ⑩ 비고 ⑪ 단위 ⑫ 출처 ⑬ 버전 ⑭ 전역 어휘 식별자(IRI)**<br><br>**⑪ 단위: 측정값을 기술하는 요소에 한하여 기재한다. 단위의 전역 식별자 결합은 이 지침의 부속서 B를 참조한다.**<br><br>**⑭ 전역 어휘 식별자: 해당 요소가 기존 전역 어휘의 용어에 대응하는 경우 그 IRI를 기재하고, 대응하는 용어가 없어 새로 정의하는 경우에는 '자체 정의'로 기재한다.**<br><br>**표준초안 에디터는 ①부터 ⑭까지 모두 작성한다. 작성한 매핑은 「정보통신표준화 운영요령」 제13조제5항에 따라 제안 단계에서 선언한 어휘와 일치하여야 한다.** |

> **방법1의 특징이 마지막 문단에 있다.** ⑭ 어휘 식별자 매핑까지 **에디터(제안자)가 작성**하며, 제안 단계 선언과의 일치를 요구한다.

### 3.3 6.6 부속서 (보강)

| 현 행 | 개정(안) |
|---|---|
| 6.6 부속서<br><br>부속서는 내용으로서는 본래 표준의 본문에 포함시켜도 되는 사항이지만, 표준의 구성상 특별히 추려서 본문에 준하여 정리한 것을 말한다.<br><br>부속서 제목은 부속서 첫 번째 쪽 중앙 맨 위쪽에 위치하여야 하며, 부속서 번호 밑에 '(본 부속서는 표준 내용의 일부임)'을 표기한다.<br><br>부속서는 A, B, C 순으로 작성하며, 항목 번호 앞에 부속서 번호(알파벳)를 붙인다. …(이하 현행 유지) | (현행 유지)<br><br>**기계가독 산출물은 부속서로 작성한다. 부속서 번호는 A부터 차례로 부여한다(ISO/IEC Directives Part 2와 같은 방식). 기술규격은 제외한다.**<br><br>**가) 내장형 — 산출물을 부속서에 전문 수록한다.**<br>**요소↔전역 어휘 식별자 매핑(JSON-LD @context), 소규모 JSON Schema 등 문서에 수록할 수 있는 분량인 경우에 적용한다. 수록한 내용이 정본이다.**<br><br>**나) 참조형 — 부속서에 규범적 참조 명세를 두고, 산출물 실물은 외부 저장소에 둔다.**<br>**산출물의 분량이 많아 문서에 수록하기 곤란한 경우에 적용한다. 명세에는 다음을 기재한다.**<br>**① 공개 위치(URL) ② 판 또는 버전 ③ 무결성 확인 값 ④ 이용조건(라이선스) ⑤ 협회 보관본의 위치**<br>**참조형인 경우에도 「정보통신표준화 운영요령」 제19조의3제4항에 따라 협회가 보관하는 사본이 정본이다.**<br><br>**어느 형태이든 산출물에는 이용조건을 표시한다. 표시 방법은 형식에 따른다.**<br>**- XML Schema·Turtle·Protobuf: 주석으로 파일 머리말에 기재**<br>**- JSON Schema: 주석을 쓸 수 없으므로 최상위 `$comment` 키에 기재**<br>**- RDF 어휘: `dcterms:license` 트리플로 기재하여 기계가 해석할 수 있게 한다** |

> **형식별 라이선스 표기 방법은 국제 사례 실측에서 나왔다.** CycloneDX는 XSD에 주석으로, JSON Schema에는 `$comment` 키로 기재한다. W3C DCAT은 `dcat.ttl` 안에 `dcterms:license <https://creativecommons.org/licenses/by/4.0/>` 트리플을 두어 기계가 라이선스를 읽을 수 있게 한다.

### 3.4 6.7 부록 (보강)

| 현 행 | 개정(안) |
|---|---|
| 6.7 부록<br>부록은 표준으로 규정하고자 하는 사항은 아니나 표준을 보충하기 위해 작성한 것을 말한다.<br>- 자유 작성 부록: 표준 본문 내용을 설명하는 부록<br>- 필수 작성 부록: 지식재산권 확약서 정보, 시험인증 관련 사항, 본 표준의 연계(family) 표준 | (현행 유지)<br><br>**참조구현을 공개하는 경우 그 위치를 자유 작성 부록에 기재할 수 있다. 이 경우 다음 문구를 함께 적는다.**<br>**"참조구현은 표준의 일부가 아니며, 협회는 그 내용에 대하여 보증하지 아니한다."** |

### 3.5 부속서 B 어휘 매핑·단위 결합 지침 (신설, 선택)

현행 부속서 A(표준화기구별 영문 준용 지침)에 이어 부속서 B를 둘 수 있다. 골격은 다음과 같다.

- **B.1 전역 어휘 선택** — 기존 어휘 우선 사용 원칙, 자체 정의는 대응 용어가 없을 때로 한정
- **B.2 어휘별 이용조건** — 주요 어휘의 라이선스 상태(아래 3.6 참조)
- **B.3 @context 작성** — 요소 이름을 키로, 전역 어휘 식별자를 값으로 하는 JSON-LD @context를 6.6에 따라 부속서로 제공
- **B.4 단위 결합** — 측정값 요소의 단위 식별자(QUDT/UCUM) 결합 방법

### 3.6 부속서 B에 넣을 어휘별 이용조건 표 (초안)

실물 파일을 수집해 확인한 결과다.

| 어휘 | 이용조건 | 확인 위치 | 전재 시 유의 |
|---|---|---|---|
| W3C DCAT | CC BY 4.0 | `dcat.ttl`에 `dcterms:license` 트리플로 선언 | 출처 표시로 가능 |
| DCMI Terms | CC BY 4.0 | DCMI 문서 고지 | 출처 표시로 가능 |
| W3C PROV-O | W3C 문서·소프트웨어 라이선스 | 어휘 파일에 선언 없음, 권고안 고지 참조 | 확인 후 사용 |
| W3C SKOS | 어휘 파일에 선언 없음 | W3C 문서 라이선스에 종속 | 확인 후 사용 |
| W3C XML Schema 데이터 타입 | © W3C, All Rights Reserved + document use rules | 권고안 고지 | 확인 후 사용 |
| Schema.org | **CC BY-SA 3.0** | `docs/terms.html` | **동일조건변경허락(SA)** — 정의문을 전재하면 부속서에도 같은 조건이 미칠 수 있다. IRI로 가리키는 방식을 권장 |
| ISO/IEC (예: 19115-3) | **파일에 표시 없음** | standards.iso.org 이용약관에 종속하나 해당 페이지 접근이 제한됨 | 전재하지 아니하고 IRI 또는 인용 표준으로만 사용 |

> **Schema.org와 ISO 두 건이 실무상 주의 대상이다.** 다만 6.5.3에 따라 **IRI로 가리키기만 하면 저작권 확인 대상이 아니므로**, 매핑 방식을 택하면 두 문제 모두 발생하지 않는다.

### 3.7 부록 Ⅰ 빈번한 오류 사례 (보강)

추가할 사례 두 건.

| 오류 | 설명 |
|---|---|
| **규범 의존 어휘를 참고 문헌에 둔 경우** | 외부 어휘의 클래스·속성을 규범적으로 사용하면서 인용 표준에 등재하지 않고 참고 문헌에만 적는다. 실측 20종 중 18종에서 발견됐다 |
| **인용과 전재를 혼동한 경우** | 외부 어휘를 IRI로 가리키기만 하면서 저작권 확인 절차를 밟거나, 반대로 정의문을 옮겨 적으면서 확인을 누락한다 |

## 4. 방법1이 두지 않는 것

| 항목 | 방법1 |
|---|---|
| "공동 에디터가 보강한다"는 문언 | **없다.** 요소 정의표의 ⑭ 어휘 식별자까지 에디터(제안자)가 작성한다 |
| 어휘 전문가 배정 전제 | 없다 |

**대신 두는 장치**: 제안 단계 선언(운영요령 제13조제5항)과 요소 정의표 ⑭의 **일치 요구**, 그리고 사무국의 형식 정합성 전자 점검(운영요령 제11조제4항).
