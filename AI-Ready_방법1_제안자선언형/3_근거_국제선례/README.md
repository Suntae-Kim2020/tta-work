## 3-1과 3-2는 어떤 관계인가

**같은 것을 다르게 본 것이 아니라, 다른 것을 봤는데 일부가 만난 것이다.**

### 대상이 다르다

| | 3-1 산출물 배포 방식 | 3-2 거버넌스·절차 |
|---|---|---|
| 표본 | 표준 **16종** | 표준화 **기구 6곳** |
| 보는 것 | **파일** — `dcat.ttl` · `gml.xsd` · `bom-1.7.schema.json` | **제도 문서** — 특허정책 · URI 영속성 정책 · IETF TLP |
| 묻는 것 | 무엇을 어떻게 **배포하는가** | 누가 어떤 **절차로 정하는가** |
| 분량 | 273MB (실물 배포본) | 5.5MB (규정 문서 27건) |

### 기관은 3곳 겹치지만 본 것은 다르다

기관 구성을 대조하면 이렇다.

- **양쪽에 나오는 기관 (3곳)** — W3C · OGC · Ecma
- **3-1에만 (9곳)** — NIST · HL7 · ISO · LoC · SPDX · DCMI · DDI · Schema.org · MLCommons
- **3-2에만 (3곳)** — IETF · OASIS · ITU-T

겹치는 3곳도 **수집한 문서가 하나도 겹치지 않는다.**

| 기관 | 3-1에서 본 것 | 3-2에서 본 것 |
|---|---|---|
| **W3C** | `dcat.ttl`·`dcat.rdf`·`dcat.jsonld` (어휘 파일) | 프로세스 문서 · 특허정책 · **URI 영속성 정책** · 문서/소프트웨어 라이선스 |
| **OGC** | `gml.xsd` 모듈 29개 | 정책 개요 · **스키마 저장소 운영 정책** · CITE 적합성 시험 |
| **Ecma** | ECMA-424 PDF · `bom-*.xsd/json/proto` | **TC39 프로세스** · 제안 목록 · 규정(by-laws) |

W3C를 예로 들면 — 3-1은 어휘 파일 안에 `dcterms:license` 트리플이 있다는 **사실**을 봤고, 3-2는 URI를 영구히 유지하겠다는 기관 **약속의 문안**을 봤다.

### 결론이 만나는 지점 두 곳 — 중복이 아니라 보강이다

| 만나는 지점 | 3-1이 보인 것 | 3-2가 보인 것 |
|---|---|---|
| **Ecma의 이중 트랙** | GitHub에서 배포되는 스키마가 ECMA-424로도 발간된다는 **배포 사실** | 그것이 Ecma 규정상 **어떤 절차로** 발간되는가 |
| **문서와 코드의 라이선스 이원화** | Schema.org가 어휘(CC BY-SA)와 빌드도구(Apache-2.0)를 나눈 **실물** | W3C·IETF가 그것을 **규정으로 어떻게 표현**하는가 |

이 두 지점은 **"실제로 이렇게 한다"(3-1)와 "그 근거 규정이 이렇다"(3-2)가 짝을 이루므로 심의에서 특히 강한 조합**이다.

### 조문별로 보면 역할이 갈린다

| 방법1 조문 | 3-1이 대는 근거 | 3-2가 대는 근거 |
|---|---|---|
| 제19조의3제2항 **병행형** | **LoC·DDI·OGC의 병행 게시 실물** | — |
| 제19조의3제3항 참조형 예외 | ECMA-424 · FHIR XSD 323개 | — |
| 제19조의3제6항 보관본 정본 | CycloneDX 이중 트랙 | W3C URI 영속성 정책 문안 |
| 제19조의3제7항 파일 내 표시 | METS·DDI 표기 / ISO 무표기 | IETF TLP 제4.d조 |
| 제19조의3제8항 **참조구현 배제** | — | **IETF TLP 제4조** |
| 제19조의2 **공동 에디터 미설치** | — | **Ecma TC39 챔피언 모델** |
| 작성지침 6.6 형식별 표기 | CycloneDX `$comment` · W3C 트리플 | — |

**두 조문(제19조의3제8항 · 제19조의2)은 3-2 없이는 근거가 없다.** 파일을 아무리 뜯어봐도 "코드를 표준에서 어떻게 다루는가", "누가 스키마를 쓰는가"는 나오지 않기 때문이다. 반대로 **병행형은 3-1의 실물 관찰에서만** 나온다.

## 선례의 무게 — 표준화 기구 여부

TTA는 표준화 기구다. 따라서 **같은 성격의 기구가 한 선택**이 선례로서 힘이 있다. 3-1의 16개 사례를 그 기준으로 표시해 둔다.

| 구분 | 사례 | 선례로서의 무게 |
|---|---|---|
| **공식 국제 표준화 기구** | ISO 19115-3 · OGC GML · W3C DCAT · W3C PROV-O · HL7 FHIR · Ecma CycloneDX | **가장 높다.** TTA와 같은 성격의 기구가 한 선택 |
| **국가기관·공공기관** | NIST OSCAL · NIST AI RMF/CPRT · LoC PREMIS · LoC MODS · LoC METS | **높다.** 공적 표준을 발간하는 기관. 다만 법적 기반(미국 저작권법 제105조)이 국내와 다른 점은 유의 |
| **표준 단체 — 국제표준화 완료** | SPDX(ISO/IEC 5962) · DCMI(ISO 15836) · DDI Alliance | **있다.** 컨소시엄에서 출발했으나 정식 국제표준·학술 표준으로 채택됐다 |
| **기업·기술 컨소시엄** | Schema.org(구글·MS·야후·얀덱스) · MLCommons Croissant | **참고 수준.** 표준화 기구가 아니므로 "TTA도 이렇게 하자"의 근거로는 약하다. 다만 AI-Ready 논의와 문제의식이 가장 가까워 기술적 참고로 남긴다 |

**심의에서 인용할 때** — 위 순서대로 근거의 강도가 다르다. Schema.org·Croissant를 근거로 들 때는 "표준화 기구는 아니지만 기술적으로 참고할 만한 사례"라고 밝히는 편이 안전하다.
