# [별지 제21-1호 서식(안)] AI-Ready 자가점검표 — 방법1

「정보통신표준화 운영요령」 제21조제5항 관련 · 방법1(제안자 선언형) · v0.1

표준안 상정 전 작성한다. 제안 단계의 「기계가독 산출물 선언서」(별지 제11-1호)에서 정한 목표를, 완성된 표준초안이 실제로 충족했는지 점검한다.

**누가, 언제 쓰나.** 표준초안을 다 작성한 뒤에 쓴다. 초안을 작성한 에디터가 스스로 점검해 채우고, 소관 기술위원회에 올릴 때 기술위원회등의 장이 확인하여 표준안과 함께 제출한다(제21조제5항).

**무엇을 다루나.** 1부는 7개 구성요소 달성 등급, 2부는 문서 정합성, **3부는 선언과 산출물의 일치**, **4부는 산출물 요건 이행**, 5부는 작성·확인이다. 3부와 4부가 방법1의 핵심이다 — 어휘 전문가의 사전 검증이 없으므로 이 두 부가 품질 관문 역할을 한다.

## 1. AI-Ready 구성요소 달성 점검

각 구성요소의 현재 등급(0 미충족 / 1 부분 / 2 충족)과 증빙 위치를 적는다. 등급 기준은 별표 제10호 제1부에 따른다.

**등급 기준 요약.** 0 = 해당 요소를 다루지 않음, 1 = 산문·표로만 있고 기계가 읽는 형식은 아님, 2 = 기계가 읽는 형식(IRI·@context·SHACL 등)으로 갖춤.

| 구성요소 | 무엇을 보는가 | 목표 (선언) | 현재 등급 | 증빙 (초안의 어디에) | 묶음 |
|---|---|---|---|---|---|
| ① 시맨틱 | 요소의 뜻을 전역 어휘(IRI)에 연결했나 | | | | L1 |
| ② 신태틱 | 그 매핑을 규범 직렬화로 냈나 | | | | L1 |
| ③ 데이터 모델 | 값 형식·제약을 기계검증 스키마로 형식화했나 | | | | L2 |
| ④ 출처/계보 | 데이터의 생성·가공 내력을 형식화했나 | | | | L2 |
| ⑤ 운영 시맨틱 | (ML만) 학습·검증 분할·역할을 선언했나 | | | | L3 |
| ⑥ 품질 프로파일 | 품질을 형식 어휘로 붙였나 | | | | L3 |
| ⑦ 접근/사용 제약 | 라이선스·이용조건을 **데이터 수준**에서 명시했나 | | | | L3 |
| **합계 / 성숙도** | | | ____ / ____ | | |

**성숙도 계산.** 등급 합계 ÷ (적용 구성요소 수 × 2). ⑤는 특정 ML 학습·검증 데이터세트를 기술하는 표준에만 적용한다. 비-ML 표준과 ④ 품질 지표 프로파일은 ⑤를 N/A로 두고 분모를 **12**로, 그 외는 **14**로 계산한다.

> ⑦은 그 표준을 따라 쌓인 **데이터**의 이용조건이다. 산출물(스키마) 자체의 이용조건은 4부에서 따로 점검한다.

## 부기 — 방법2 서식과 달라지는 지점

| | 방법1 | 방법2 |
|---|---|---|
| 작성자 | **에디터 1인** | 에디터 + 공동 에디터 |
| 3부 | **선언 일치 확인 (신설)** | 없음 |
| 4부 | **산출물 요건 이행 확인 (신설)** | 제출 산출물 확인만 |
| 0. 선언 요약 | 어휘·산출물 형식·부속서 형태·공개·이용조건까지 | 프로파일·목표 수준만 |

1부(구성요소 달성)와 2부(정합성)는 두 방법이 같다.
